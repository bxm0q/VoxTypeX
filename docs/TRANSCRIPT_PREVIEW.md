# Предпросмотр во время диктовки

В настройках включите «Текст во время записи → Предпросмотр в индикаторе».
Нужны включённые VAD и индикация. Предпросмотр включён по умолчанию;
режим «Выключен» возвращает прежнюю обработку только после отпускания PTT.

Во время записи меняется текст в overlay. Это гипотеза: окончательный
результат пересчитывается по полной записи и может отличаться. В стороннее
поле передаётся только один итог. Esc очищает предпросмотр и отменяет вставку.
Ручной ввод или смена цели сохраняют прежний запрет на вставку.

## Возможности движков

| Выбранная модель | Нативные partial_results / streaming | Доступный режим |
|---|---|---|
| Whisper tiny / base / small | нет / нет | Batch-предпросмотр |
| GigaAM v3 RU, компактная / точная | нет / нет | Batch-предпросмотр, затем Whisper при ошибке |
| Moonshine Base UK | нет / нет | Batch-предпросмотр, затем Whisper при ошибке |
| Parakeet TDT v3 UK | нет / нет в текущем адаптере | Batch-предпросмотр; тяжёлая модель может обновляться редко |
| Canary 180M EN, компактная / точная | нет / нет | Batch-предпросмотр, затем Whisper при ошибке |
| Автоматический язык | нет / нет | Предпросмотр Whisper с определением языка |

Все подключённые адаптеры используют `batch_preview`. Возможности
`partial_results` и `streaming` в `SpeechEngine.capabilities` выключены.

Первичные описания API: [faster-whisper](https://github.com/SYSTRAN/faster-whisper),
[transcribe.cpp](https://github.com/handy-computer/transcribe.cpp/blob/main/docs/bindings.md).
Live-typing не поддерживается.

## Обработка и ограничения

- PortAudio callback по-прежнему только копирует PCM в ограниченный буфер.
  DSP-поток ведёт VAD-интервалы; снимок обработанного PCM берётся под короткой
  блокировкой вне callback. Формат — mono PCM16 / 16 кГц.
- Окно по умолчанию 8 секунд, допустимо 4–20. Длинная речь идёт по окнам
  с перекрытием 1 секунда. Пауза с hangover закрывает фразу. Короткий или
  пустой закрытый сегмент пропускается, следующая речь не блокируется.
- Повторные гипотезы заменяют хвост. Общий префикс двух гипотез, кроме двух
  последних слов, закрепляется. Закрытая фраза фиксируется целиком. На
  перекрытии удаляется совпадающий суффикс/префикс; отдельные VAD-фразы
  сохраняют намеренные повторы. Это эвристика предпросмотра, без гарантии
  точности или правильной границы каждого слова. Финал собирается независимо.
- Первый активный запрос ждёт около секунды контекста; короткая завершённая
  фраза может появиться раньше. Настройка интервала — 1–10 секунд, по умолчанию
  1.5. Интервал ограничивает частоту запросов. После медленного
  inference выдерживается пауза не короче времени этого inference.
- Есть один preview-поток, одно окно в работе и mailbox с одним событием.
  Стабильный текст и PCM ограничены общим пределом записи 120 секунд.
  При холодном старте модели или короткой записи гипотеза может не успеть
  появиться. Тихая речь с неуверенным online VAD может появиться лишь в финале.
- Перед финальным decode preview-context отменяется; владелец ждёт остановки
  inference. При превышении ожидания финальный decode не запускается, приложение
  сообщает ошибку и закрывает обработку. Две задачи на одной GPU не создаются.
  Отмена активного native-запроса может выгрузить модель и увеличить задержку финала.
- Номера `session_id`, `generation`, `sequence` защищают mailbox и overlay от
  позднего ответа. Финал закрывает поколение для partial-событий. Смена фокуса,
  Esc, настройки и выход отменяют preview-context и очищают текст.
- Preview-ошибка отключает предпросмотр этой записи; обычное финальное
  распознавание остаётся доступным. Ошибки журналируются по категории/типу.
  Текст и аудио в событиях находятся только в памяти и не пишутся в логи.

## Измерения и воспроизводимая проверка

`RecordingService.last_preview_metrics` содержит время первой непустой
гипотезы от PTT и отдельно `first_visible_ms` после paintEvent overlay в GUI,
число запросов/fallback, wall time inference, CPU-секунды
родительского процесса и ASR-worker, задержку финала от release до результата.
`cpu_percent` — сумма CPU-секунд / длительность preview × 100: **100% означает
одно логическое ядро**, а не весь процессор. Загрузка модели входит в запрос,
если он холодный. CPU-время GPU-вычисления не измеряет загрузку GPU; отменённый
процесс может не успеть вернуть свой CPU-счётчик. Неполные измерения помечаются
`worker_cpu_measured=false`, число неполученных счётчиков — `unmeasured_calls`.
В этом случае CPU% является нижней оценкой. Числовые метрики записываются без транскрипта.

Ручной smoke использует имеющийся публичный WAV и уже установленные модели.
Открывается отдельный процесс с двумя пустыми полями; Windows-вставка
разрешается только в захваченную тестовую цель. Во время прогона не меняйте
фокус, кроме специального сценария. Скрипт не записывает звук с микрофона.

```powershell
$env:VOXTYPEX_MODEL_DIR = 'C:\Users\USER\AppData\Local\VoxTypeX\models'
$env:VOXTYPEX_SMOKE_MODEL = 'tiny'
$env:VOXTYPEX_PREVIEW_BACKEND = 'faster-whisper' # либо transcribe-cpp
$env:VOXTYPEX_PREVIEW_LANGUAGE = 'ru' # uk / en
python packaging/preview_smoke.py C:\Temp\preview-run C:\Clips\ru-pcm16.wav
# Для готовой сборки:
.\VoxTypeX.exe --smoke-preview C:\Temp\preview-frozen C:\Clips\ru-pcm16.wav
```

Каталог результата должен быть новым. WAV: 16 кГц / mono / PCM16,
желательно 15–25 секунд. Сначала выполняется warmup; затем WAV подаётся
порциями по 20 мс в реальном времени. `result.json` содержит только проверки
и метрики; `overlay.png` — снимок гипотезы публичного тестового текста.
Для ошибок фокуса, отмены и выхода повторите с
`VOXTYPEX_PREVIEW_CASE=changed`, `cancel`, `close`. В этих режимах оба поля
должны остаться пустыми. Запись с микрофона проверяется по
[ручному сценарию](MANUAL_SMOKE_TEST.md).
