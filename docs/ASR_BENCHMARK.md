# Воспроизводимое сравнение ASR

Для RU/UK/EN сравниваются компактный и точный профили, Whisper tiny/base/small.
Все варианты получают одинаковый mono PCM16 WAV 16 кГц; устройства принудительно CPU.
Первый warmup не входит в WER/CER и время измерения. RAM включает загрузку модели.

Подготовка публичного небольшого корпуса FLEURS (CC-BY-4.0):

```powershell
python scripts/fetch_benchmark_corpus.py --help
python scripts/fetch_benchmark_corpus.py
```

Корпус закреплён на revision `70bb2e84b976b7e960aa89f1c648e09c59f894dd`.
Берутся первые 12 совпавших test WAV по порядку архива на язык. Скрипт сохраняет
исходный SHA256, итоговый SHA256, reference, лицензию и источник в manifest.
Большие архивы читаются потоком; извлекаются только выбранные WAV. Ничего не
скачивается в pytest. Собственные WAV можно описать теми же полями manifest.

Установите модели через настройки; Whisper tiny/base/small нужно один раз
скачать обычной диктовкой с выбранной моделью. Сам benchmark ничего не скачивает.

```powershell
$env:HF_HUB_OFFLINE='1'
python scripts/benchmark_asr.py --manifest .local/asr-benchmark/manifest.json --out .local/asr-benchmark/results
```

Для другого кэша передайте `--cache-dir`. `--limit-per-language 3` позволяет
сделать короткую проверку. Флаги `--variants` и `--conditions` выбирают варианты.

Измерения: сумма word/character edit distance, делённая на сумму reference words/
characters; NFKC, casefold, удаление апострофов, пунктуация заменяется пробелами,
диакритика сохраняется; CER учитывает пробелы нормализованной строки. Развёртки
чисел нет. Скорость — audio seconds / elapsed seconds, RTF — обратное отношение.
Время включает приложение и IPC после warmup. RSS процесса измеряется Windows
GetProcessMemoryInfo; для CPU VRAM равна 0, недоступный GPU-счётчик — null.

`read` — реальная публичная прочитанная речь. `noise` — тот же клип с
воспроизводимым Gaussian noise, seed 17, SNR 20 dB до PCM16 saturation.
В корпусе используется синтетический шум. Разговорная речь, акценты вне выборки
и записи с пользовательского микрофона в сравнение не входят.

Ошибки считаются пустой гипотезой и явно отмечаются. При native fallback
результат Whisper не засчитывается как точность GGUF. Отчёты JSON/CSV содержат
метрики, размеры, ревизии, устройства и категории ошибок; гипотезы не сохраняются.
Проверять скорость следует без параллельной сборки и других CPU/GPU задач.

## Выбор украинской точной модели

Выбран Parakeet TDT v3 Q8_0 как необязательный тяжёлый профиль с CC-BY-4.0.
Также исследован Orukeet. Публикуемые transcribe.cpp результаты на FLEURS Q8:
UK WER Moonshine Base 14.39%, Parakeet v3 6.84%, Orukeet 6.53%.
Это результаты автора runtime, не измерения VoxTypeX и не гарантия для диктовки.
Orukeet имеет другую лицензию и не делается обязательной зависимостью.

Первичные источники: [Moonshine UK](https://huggingface.co/handy-computer/moonshine-base-uk-gguf),
[Parakeet v3](https://huggingface.co/handy-computer/parakeet-tdt-0.6b-v3-gguf),
[Orukeet](https://huggingface.co/handy-computer/orukeet-gguf),
[FLEURS](https://huggingface.co/datasets/google/fleurs).

## Локальный прогон 15.10.2026

Windows 11 x64, Ryzen 5 5600, 16 ГБ RAM, Python 3.13.15; оба backend — CPU,
до 4 inference threads. RTX 5050 присутствует в машине, но в этом прогоне не
используется. Все 30 комбинаций завершены: 360 измеренных распознаваний,
15 отдельных warmup, 0 ошибок и 0 native fallback. Всего 36 исходных клипов:
RU 157,98 с, UK 116,82 с, EN 107,06 с.

Точные метрики, байты, SHA256, ревизии и версии библиотек сохранены в
[ASR_BENCHMARK_RESULTS.json](ASR_BENCHMARK_RESULTS.json). Здесь значения округлены.
RAM — пиковый RSS worker за загрузку, warmup и оба условия, без GUI. Для всех
строк VRAM = 0: модели работают на CPU. МБ — 1 000 000 байт, MiB — 1 048 576.
RTF 0,1 означает примерно 1 с обработки на 10 с звука; меньше — быстрее.
Это один прогон без интервалов повторяемости. Время зависит от нагрузки ОС;
выраженная разница RTF между условиями не является свойством точности модели.
